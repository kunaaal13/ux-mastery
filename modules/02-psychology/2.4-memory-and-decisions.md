# 2.4 Memory & Decision-Making

## In one line

People hold very little in mind at once, recognise far better than they recall, and decide with fast heuristics that a designer can either support or exploit.

## Basic

### Working memory

Miller's 1956 paper gave "seven plus or minus two," but modern estimates for unrelated items are lower — roughly **four chunks** for most people under realistic conditions. A chunk is a meaningful unit, so expertise expands capacity: "BBC" is one chunk to you, three letters to a child.

Design consequences:
- Never require carrying a value across screens. Show it.
- Chunk long strings: `4242 4242 4242 4242`, not `4242424242424242`.
- Keep the number of items to compare simultaneously small, or provide a comparison view so memory is not the mechanism.

### Recognition over recall

Recognition (seeing the answer among options) is far easier than recall (producing it from memory). This is the reason for:

- Menus and visible navigation rather than commands you must remember
- Autocomplete and recent items
- Showing entered data at confirmation instead of asking users to remember it
- Icon **plus** label, since an icon alone is a recall test for its meaning

The exception: expert, high-frequency users benefit from recall-based interfaces (keyboard shortcuts, command palettes) because recall is faster once learned. Modern answer: **offer both** — a command palette layered over a visible UI serves both populations.

### Recognition has limits too

Recognition fails when options are numerous and similar — 40 near-identical labels is a search problem, not a recognition benefit.

## Deeper

### Heuristics and biases that show up in interfaces

| Bias | What it does | Design use |
| --- | --- | --- |
| **Anchoring** | First number seen frames all later judgements | Pricing pages show the highest tier first, or list the "was" price |
| **Framing** | "90% fat free" vs "10% fat" — same fact, different response | Frame outcomes in gains for adoption, losses for retention |
| **Loss aversion** | Losses feel ~2x gains | "You will lose your streak" outperforms "keep your streak" |
| **Default effect / status quo bias** | People keep the preselected option | Defaults are the most powerful design lever; also the most ethically loaded |
| **Social proof** | Others' behaviour guides ours | Review counts, "12 people booked today" — must be true |
| **Availability** | Easily recalled examples feel more probable | Recent errors dominate perceived reliability |
| **Decoy effect** | An asymmetrically dominated third option shifts choice | Common in three-tier pricing |
| **Sunk cost** | Invested effort resists abandonment | Progress bars raise completion; also traps users |
| **Confirmation bias** | We seek evidence supporting existing belief | *Your* biggest research risk — write questions that could disprove you |

**Ethical line:** using loss aversion to help someone keep a habit they chose is design. Using it to prevent cancellation is a dark pattern (Module 13). The test: *does this technique serve a goal the user actually holds?*

### Choice architecture

Every arrangement of options nudges. There is no neutral presentation, so the responsibility is to nudge toward the user's own interest:

- **Order** — first and last positions are privileged (serial position effect, Module 03).
- **Number** — more options increase perceived freedom but slow decisions and can reduce satisfaction (choice overload; the effect is real but context-dependent, strongest when options are similar and the user lacks preferences).
- **Grouping** — categories change what feels comparable.
- **Defaults** — the strongest lever; opt-in vs opt-out changes participation dramatically.
- **Descriptions** — the attribute you show becomes the attribute compared.

### Satisficing

Users do not optimise; they take the first option that seems good enough (Herbert Simon's "satisficing"). Krug's rule follows: people muddle through, clicking the first plausible thing. Consequences: label the first plausible thing accurately, and make wrong turns cheap to reverse — recovery matters more than prevention for low-stakes choices.

### Recall decay and re-entry

Memorability (Nielsen's third component) matters for tools used monthly. If your product is used rarely, invest in re-entry cues: a "where you left off" summary, persistent breadcrumbs, and stable structure. Changing your navigation resets everyone's learned recall — the reason redesigns often show a temporary metric dip.

## Applications

**Example — confirmation screens.** Showing the entered address at confirmation is not redundancy; it converts a recall task into a recognition task at exactly the moment errors are most expensive.

**Example — the ethical fork.** Two products both use loss framing. A savings app says "skipping this transfer costs you ₹4,200 by next year" — the user's own goal. A subscription says "cancel and lose your history forever" while quietly holding the data anyway — coercion using a false claim. Same mechanism, opposite ethics.

**Do this / not that**

- *Not that:* An icon-only toolbar with 12 icons for an occasional-use tool.
- *Do this:* Icon + label, or labels revealed on hover *and* a command palette for experts.

## Interview angle

**Common questions**
- "How would you increase completion of this multi-step form?"
- "What is the ethical line on persuasive design?" (Increasingly common, especially at larger companies.)
- "Why is recognition better than recall? When is it not?"

**For the completion question**, hit memory and decision levers explicitly: reduce required decisions with defaults, chunk fields into meaningful groups, show progress (goal-gradient effect), never require carrying data between steps, allow save-and-resume, and put the cheapest questions first to build commitment — then note the trade-off: front-loading easy questions raises completion but can lower data quality if users rush.

**For the ethics question**, give a usable test rather than a sentiment: "Would I be comfortable showing the user exactly why this works? Does the technique help them reach a goal they hold themselves? Is the reverse action as easy as the forward action?" Three questions, and you can answer any dark-pattern probe with them.
