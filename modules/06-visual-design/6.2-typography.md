# 6.2 Typography

## In one line

Type is the interface — most products are 95% text, so typographic decisions carry more usability weight than any other visual choice.

## The variables

| Variable | What it controls | Practical guidance |
| --- | --- | --- |
| **Typeface** | Voice, legibility | One or two families. A neutral, well-hinted UI face for interface text; a display face only for headlines if brand demands it. |
| **Size** | Hierarchy, readability | Body text ~16 px on web (browser default), never below 14 px for sustained reading. Mobile body 16–17 pt. |
| **Weight** | Emphasis, hierarchy | Use 2–3 weights (e.g. 400/500/700). More weights blur the steps. |
| **Line height (leading)** | Readability | ~1.4–1.6× for body text; tighter (1.1–1.25) for large headlines. Longer lines need more leading. |
| **Measure (line length)** | Reading comfort | 45–75 characters per line for body text; ~66 is the classic target. Long measures cause line-tracking errors on return sweeps. |
| **Letter spacing (tracking)** | Texture, legibility | Slight negative tracking on large headlines; slight positive on all-caps and small text. Never track body text. |
| **Case** | Emphasis, scanning | All-caps is fine for short labels, poor for anything longer — it removes word-shape cues and slows reading. |
| **Alignment** | Structure | Left-align body text in LTR scripts. Justified text without hyphenation creates rivers. Centre only short headlines. |
| **Colour/contrast** | Legibility | See Module 10 — 4.5:1 for body, 3:1 for large text at WCAG AA. |

## The type scale

Use a **modular scale** — each step multiplied by a fixed ratio — so sizes are decidable rather than arbitrary:

```
Ratio 1.25 (major third), base 16:
  16 → 20 → 25 → 31 → 39 → 49
Ratio 1.2 (minor third), base 16:
  16 → 19 → 23 → 28 → 33 → 40
```

Practical UI scale (rounded, 5–7 steps is plenty):

```
12  caption / metadata
14  secondary body, dense UI
16  body (default)
20  section heading
24  page heading
32  display
```

Fewer steps with clear jumps beats many steps with subtle differences. If two sizes are within 2 px of each other, they read as an inconsistency rather than a hierarchy.

## Readability rules that carry the most weight

1. **Measure before size.** A 16 px line running 120 characters is harder to read than a 14 px line at 65 characters. Constrain the container.
2. **Leading scales with measure.** Wider columns need more line height to prevent the eye losing its place on the return sweep.
3. **Contrast is not optional.** Light grey body text on white is the most common accessibility failure in modern products, and it disproportionately affects older users and bright-light conditions.
4. **Hierarchy through weight before size.** Small caps-height differences plus weight often produce a cleaner hierarchy than large size jumps, especially in dense UI.
5. **Numbers deserve attention.** Use tabular (monospaced) figures for anything in a column — prices, times, statistics — so digits align vertically.

## Text in interfaces specifically

- **Truncation:** always know what happens to long content. Truncate with an ellipsis *and* provide access to the full value (tooltip, expand, wrap). Never truncate the most identifying part of a string — for filenames, truncate the middle.
- **Localisation:** German runs ~30% longer than English; some scripts need more line height; right-to-left languages mirror layout. Design with the longest plausible string, not "Lorem ipsum."
- **Empty and error text** deserves the same typographic care as headlines — it is read at the moment of highest stress.
- **Sentence case beats Title Case** for most UI labels: it is faster to scan and avoids inconsistent capitalisation rules.

## Typography and voice

Type carries tone before content does. A dense, tightly-tracked grotesque reads as technical; a large, generously-led serif reads as editorial. Pick a voice that matches the product's job, then hold it — inconsistency reads as carelessness, which for financial and health products directly reduces perceived credibility.

## Applications

**Do this / not that**
- *Not that:* 13 px grey (#9A9A9A) body text at 1.2 line height, full container width.
- *Do this:* 16 px near-black at 1.5 line height, container capped around 65 characters. This single change often improves comprehension and time-on-task more than any layout work.

## Interview angle

**Common questions**
- "How do you choose type sizes?"
- "What is wrong with the typography on this screen?"
- "How would you make this dense screen more readable?"

**Model answer for choosing sizes:** "I use a modular scale so the steps are systematic rather than arbitrary — usually a 1.2 or 1.25 ratio from a 16 px base — and I keep it to five or six steps, because steps closer than a couple of pixels read as an inconsistency rather than a hierarchy. Then I check the three things that actually determine readability: measure around 45–75 characters, line height around 1.5 for body, and contrast at least 4.5:1."

Citing measure and contrast is what marks a typographic answer as informed rather than decorative.
