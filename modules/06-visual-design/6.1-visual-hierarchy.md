# 6.1 Visual Hierarchy

## In one line

Visual hierarchy is the deliberate ordering of what the eye sees first, second, and third — and if you do not design it, the layout decides it for you, usually badly.

## The six tools

Ranked roughly by strength:

1. **Size** — the strongest and bluntest. Doubling a number's size makes it the subject of the screen.
2. **Weight & contrast** — a bold or high-contrast element outranks a light one of the same size. Contrast against the *background* is what matters, not absolute darkness.
3. **Colour** — a saturated element among muted ones pops. Weak on its own; strong when combined with size or weight, and unusable as the sole encoding (Module 10).
4. **Space** — isolation creates importance. An element surrounded by generous space reads as significant even at modest size. The most underused tool.
5. **Position** — top-left (in LTR reading order) and optical centre carry weight; so do the first and last positions in a sequence (serial position, Module 03).
6. **Style/treatment** — enclosure, elevation, a background tint, an underline. Useful for grouping and state, weak for pure emphasis.

**The rule of relativity:** emphasis is relational. Nothing is emphasised in absolute terms — it is emphasised *relative to its neighbours*. Adding emphasis to more elements subtracts it from all of them (Von Restorff, Module 03).

## Building a hierarchy

1. **Rank the content first, in words.** Write the screen's elements in priority order before opening a design tool: primary information, primary action, supporting information, secondary actions, metadata. If you cannot rank them in words, no amount of styling will fix it.
2. **Assign a level to each rank.** Three levels are usually enough; four is the practical ceiling. Beyond that the differences stop being perceptible.
3. **Use two or more tools per level.** Size alone produces a monotonous hierarchy; size + weight + colour value gives a clear, robust step.
4. **Verify by squinting** (Module 04) — the order that survives blur is the real hierarchy.

## Common failures

| Failure | Cause | Fix |
| --- | --- | --- |
| Everything shouts | Too many emphasised elements | Demote ruthlessly; one primary per view |
| Everything whispers | Insufficient contrast between levels | Increase the *step size* between levels, not the number of levels |
| The eye has no entry point | No dominant element | Establish one clear focal point |
| Hierarchy contradicts the task | Styled by aesthetics, not priority | Re-rank content in words and restyle |
| Hierarchy collapses on mobile | Levels expressed by position, not by intrinsic properties | Encode hierarchy in size/weight so it survives reflow |

## Emphasis budget

Treat emphasis as currency, with a fixed amount per view:

- **1 primary action** — filled, high contrast.
- **0–2 secondary actions** — outlined or tinted.
- Everything else — text-level.
- **1 focal content element** — the number, image, or headline the screen exists for.
- Badges, alerts, and highlights: fewer than you think. Every additional one devalues the rest.

## Hierarchy for interactive elements specifically

Users must be able to tell, without clicking: what is clickable, what is primary, what is destructive, and what is currently selected. That is four distinctions, and they need to be visible simultaneously. A common bug is using the same treatment for "selected" and "primary," which makes selection state unreadable.

## Applications

**Example — a transaction row.** Rank: amount (primary), merchant (secondary), date and category (metadata), status (only when abnormal). A typical mistake is styling merchant and amount at the same weight, so scanning a statement requires reading rather than glancing.

**Example — a dashboard.** Eight equal tiles have no hierarchy, so users read all eight every visit. Making one or two dominant means the answer to "is anything wrong?" takes 200 ms instead of five seconds.

**Do this / not that**
- *Not that:* Making a heading bigger to fix a weak hierarchy while leaving everything else unchanged.
- *Do this:* Demote the surrounding elements. Lowering the noise floor is usually cheaper and more effective than raising the signal.

## Interview angle

**Common questions**
- "Walk me through the hierarchy on this screen."
- "How would you improve this layout?"
- "What makes a design feel professional?"

**Model narration:** "My eye goes first to X because of its size and contrast, then to Y because it is isolated by space, then to the button because it is the only filled element. That order matches what I would expect the primary task to be — if the task were actually Z, the hierarchy is fighting it, and I would demote X rather than enlarge Z."

**For "what makes design feel professional?"** — a specific answer beats vibes: consistent spacing on a scale, a limited type scale with clear steps, restrained colour with one accent, alignment to a small number of edges, and consistent treatment of the same element across screens. Then name the deeper cause: *fewer arbitrary decisions*. Professional-looking work is mostly the absence of unexplained variation.

## Check yourself

1. Rank the six hierarchy tools by strength and name the most underused.
2. Why does adding emphasis to more elements reduce emphasis overall?
3. What is the practical maximum number of hierarchy levels, and why?
4. Give the emphasis budget for a single view.
5. What is the cheaper alternative to enlarging your primary element?
