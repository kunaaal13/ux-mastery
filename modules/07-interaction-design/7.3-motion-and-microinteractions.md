# 7.3 Motion & Microinteractions

## In one line

Motion should explain something — where a thing came from, what changed, or what is coming — and any motion that does not is a tax on attention.

## The jobs motion can legitimately do

1. **Continuity of context.** An element expanding into a detail view tells you where you are and how to get back. Without it, the user must re-orient from scratch.
2. **Direction of attention.** Movement is the strongest pre-attentive attribute (Module 02); use it for genuinely important, infrequent events.
3. **Perceived responsiveness.** An immediate press animation makes a slow system feel acknowledged (Doherty).
4. **Spatial model.** Sheets rising from the bottom, panels sliding from the side — consistent origins teach a spatial layout that users navigate by memory.
5. **Feedback and state change.** A toggle whose knob travels tells you the state changed and in which direction.
6. **Delight, sparingly.** A moment of personality at a peak or an ending (Peak–End, Module 03) — never spread evenly across the product.

If a motion serves none of these, remove it.

## Timing and easing

| Duration | Use |
| --- | --- |
| **≤100 ms** | Micro feedback: hover, press, small state toggles |
| **150–250 ms** | Most UI transitions: dropdowns, tooltips, small element moves |
| **250–400 ms** | Larger transitions: sheets, page changes, expanding cards |
| **>400 ms** | Rarely justified; feels sluggish because it exceeds the Doherty window |

Larger objects and longer distances need slightly longer durations to feel physically plausible; small elements need shorter ones.

**Easing:**
- **Ease-out** for elements entering — fast start, gentle settle. This is the default for most UI.
- **Ease-in** for elements leaving.
- **Ease-in-out** for elements moving between two on-screen positions.
- **Linear** only for continuous, non-physical motion (spinners, progress).
- **Spring physics** for direct-manipulation gestures, where the motion should follow the finger and settle naturally.

## Microinteractions

Dan Saffer's four-part model — useful because it forces you to design the whole loop, not the animation:

1. **Trigger** — what starts it (user action or system event).
2. **Rules** — what happens, and what is and is not possible.
3. **Feedback** — how the user knows.
4. **Loops and modes** — what happens over time and on repetition (does it change after the tenth use? does it stop celebrating?).

Point 4 is the one that gets skipped and the one that matters over months: a celebration animation on every save is delightful once and enraging by Tuesday.

## Reduced motion and accessibility

Motion is not neutral. For users with vestibular disorders, large-scale movement, parallax, and zooming transitions can cause nausea, dizziness, and migraine.

- Respect **`prefers-reduced-motion`**. The reduced variant should not be "no feedback" — replace movement with a cross-fade or an instant state change, keeping the information.
- WCAG 2.2 requires that motion triggered by interaction can be disabled (2.3.3, AAA), and that anything auto-playing for more than 5 seconds can be paused (2.2.2, A).
- Never use motion as the only signal for a state change.

## Anti-patterns

- **Motion on frequently repeated actions** — a 300 ms animation on an action performed 200 times a day costs a minute a day and quickly reads as lag.
- **Animation that blocks input** — the user should be able to act before the animation finishes; interruptible transitions are mandatory in professional tools.
- **Decorative loops** — perpetually animating illustrations near text destroy reading.
- **Inconsistent origins** — a panel that slides from the left on one screen and fades in on another breaks the spatial model.
- **Long onboarding animations** that cannot be skipped.

## Applications

**Do this / not that**
- *Not that:* A 500 ms bounce every time an item is added to a list.
- *Do this:* A 150 ms ease-out slide-and-fade that shows *where* the item landed, and no bounce.

## Interview angle

**Common questions**
- "How do you decide when to use animation?"
- "What is a microinteraction?"
- "How does motion affect accessibility?"

**Model answer for the first:** "I ask what the motion explains. If it shows where something came from, directs attention to something important, gives feedback, or communicates a spatial model, it earns its place. If it exists to look modern, it costs attention and time and I cut it. Then I check frequency — anything the user does dozens of times a day should be at the fast end or instant — and I make sure there is a reduced-motion variant that keeps the information while removing the movement."

Mentioning `prefers-reduced-motion` unprompted is a strong, specific signal in a craft interview.
