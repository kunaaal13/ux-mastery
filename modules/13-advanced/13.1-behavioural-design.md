# 13.1 Behavioural Design

## In one line

Behaviour happens when motivation, ability, and a prompt coincide — design mostly works by increasing ability and improving the prompt, because motivation is the hardest to move.

## The Fogg Behaviour Model

**B = MAP** — Behaviour occurs when **Motivation**, **Ability**, and a **Prompt** converge at the same moment.

- If motivation is high but ability is low, the behaviour fails — the person wanted to but it was too hard.
- If ability is high but motivation is low, a prompt may still trigger it if the action is trivial.
- **No prompt, no behaviour**, regardless of the other two.

Design implications, in order of practical leverage:
1. **Increase ability** — make the action smaller, faster, cheaper, and less scary. This is where design has the most reliable effect.
2. **Improve the prompt** — right moment, right place, right framing. Contextual prompts beat louder prompts.
3. **Support motivation** — meaning, progress, social proof, and connection to a goal the user already holds.

**Tiny habits:** shrink the behaviour until motivation is irrelevant (floss one tooth; write one sentence). In products: "add one item", "read one card".

## The Hook Model (Nir Eyal)

**Trigger → Action → Variable Reward → Investment**, looping.

- **Trigger** — external at first (notification, email), becoming internal (boredom, anxiety, curiosity).
- **Action** — the simplest behaviour done in anticipation of reward.
- **Variable reward** — unpredictability sustains engagement far better than fixed rewards; this is the mechanism behind feeds and pull-to-refresh, and it is the most powerful and most abusable part of the model.
- **Investment** — the user puts something in (content, connections, preferences, reputation), which increases the value of returning and raises switching cost.

**Read it as a description of a mechanism, not a licence.** The same loop that helps someone build a language-learning habit is what makes a slot machine work. Eyal himself distinguishes "habit" from "addiction" by whether the behaviour serves the user's own interests.

## Habit formation and streaks

- **Cue → routine → reward** (Duhigg's loop) is the same skeleton.
- **Streaks** work because of loss aversion and the goal-gradient effect (Module 03) — and they can turn into anxiety machines. The ethical implementations offer streak repair, pauses, and freezes, because the goal is the habit, not the number.
- **Reminders** are prompts; their value collapses if they fire when action is impossible. Timing beats frequency.

## The ethical line, made usable

Ask three questions about any behavioural mechanism:

1. **Whose goal does this serve?** If it advances a goal the user holds themselves, it is design. If it only advances a business goal at the user's expense, it is manipulation.
2. **Would the user be comfortable if I explained exactly how this works?** ("We show a countdown to make you decide faster." "We put the cancel link three levels deep.")
3. **Is the reverse as easy as the forward?** Cancelling as easy as subscribing; unfollowing as easy as following; opting out as easy as opting in.

Failing any of the three is your signal to stop, regardless of how well it performs.

## Interview angle

**Common questions**
- "How would you increase engagement with this feature?"
- "How do you build a habit-forming product responsibly?"

**For the engagement question**, structure with B=MAP and then immediately qualify: "I would look at ability first — is the action too big, too slow, or too uncertain — because that is where design moves the needle most reliably. Then the prompt: is it arriving at a moment when the user can actually act? Motivation I would treat last, and mostly by connecting the action to a goal the user already has rather than manufacturing one. And I would want to know what 'engagement' means here, because for some products more sessions is a failure signal — I would pair it with a satisfaction or task-success guardrail."

That final qualification is the difference between a designer and a growth-metric technician.
